Making one chart
do the work of five

Role Product Designer, end to end
Company SafetyCulture
Domain Analytics
Platform Web
Status Released

Overview

Customers used KPI thresholds to judge performance at a glance — but charts supported only a single KPI, with no custom ranges or colour coding. I designed multiple-KPI support across SafetyCulture's chart library, letting customers track several targets and performance bands in a single chart.

The problem

Poor UX forcing workarounds → unlock $770K ARR

Without multiple KPIs or custom thresholds, customers resorted to two workarounds: creating several near-identical charts, or exporting data to spreadsheets and analysing it outside the platform. Both were time-consuming and undermined the value of Analytics itself. Demand was well-evidenced in customer calls and on the product feedback board.

The solution

A KPI configuration modal with two modes: single-value KPIs — up to 4 per chart, shown as line indicators with custom names and colours — and range KPIs — up to 5 performance bands defined by min/max values. The design extended the platform's existing bar-colour behaviour to multiple targets, keeping the mental model customers already had, across seven chart types: stacked, column, grouped, bar, line, timetable, and dial.

Outcome

Released to all customers on web. Post-release impact wasn't instrumented, so the honest answer is: shipped, impact not tracked — a gap I'd push to close earlier if I ran this project again.

A chart builder
you can talk to

Role Product Designer, end to end
Company SafetyCulture
Domain Analytics
Platform Web
Status Launch ready (design & spec)

Overview

I designed a conversational, AI-powered chart builder to fix the #1 complaint about SafetyCulture Analytics: that building a chart was too manual and fiddly to bother with. The project reached launch-readiness — design and spec through dogfood → beta → GA — before the roadmap shifted.

The problem

Manual, fiddly chart-building → charts created through conversation

Only ~45% of users who started building a chart actually finished it (Nov 2024 – Mar 2025). In customer calls, "the learning curve" came up repeatedly — the existing builder asked users to make a series of configuration decisions before they saw anything useful.

The approach

A natural-language chat interface that generates a chart instantly, then asks guided follow-up questions — metric → attribute → filters → chart type → config — only when needed. V1 was deliberately limited to one entry point (the Analytics landing page), excluding dashboard-level creation to avoid filter-consistency issues and match design capacity.

Outcome

Launch-ready: design and spec complete, with a staged rollout planned (dogfood → beta → GA) before the roadmap shifted and the release was paused. Success metrics were defined up front: lift completion past the ~45% baseline, and track the share of charts created via natural language as the adoption signal.
